# 착착(ChackChack) 릴리스 노트

## v1.4.0 (2025-09-09) ✨

### 🛡 개인정보보호법 컴플라이언스
- **최초 1회 개인정보 동의 기능 구현**: 신규 사용자가 첫 번째 QR코드 생성 시에만 개인정보 수집 및 이용 동의 UI 표시
- **이용자 편의성 극대화**: 기존 동의 사용자에게는 동의 절차를 생략하여 원활한 서비스 이용 지원
- **듀얼 저장 방식**: 게스트 사용자는 로컬 저장소, 로그인 사용자는 서버 데이터베이스에 동의 상태 관리
- **법적 요구사항 준수**: 개인정보보호법에 따른 최소한의 동의 절차로 법적 리스크 최소화

### 🚀 핵심 기술 구현

#### Backend API 확장
- `POST /auth/privacy-consent`: 개인정보 동의 상태 서버 저장
- `GET /auth/privacy-consent`: 현재 동의 상태 및 동의 일시 조회
- Owner 엔티티 스키마 확장:
  - `isPrivacyConsentGiven`: 동의 여부 (boolean, default: false)
  - `privacyConsentDate`: 동의 일시 (timestamp, nullable)

#### Frontend 상태 관리
- Zustand 글로벌 스토어에 개인정보 동의 로직 통합
- `checkPrivacyConsent()`: 게스트/로그인 사용자 구분하여 동의 상태 확인
- `givePrivacyConsent()`: 사용자 상태에 따른 동의 정보 저장
- AsyncStorage 유틸리티: 게스트 사용자 로컬 동의 관리

#### UX 최적화
- **조건부 UI 렌더링**: 미동의 사용자에게만 개인정보 수집 및 이용 동의 섹션 표시
- **편집 모드 제외**: 기존 QR코드 편집 시에는 동의 절차 생략
- **최소한의 개입**: 법적 컴플라이언스를 위한 필수 절차로만 제한

### 🔮 향후 기능 준비
- MyQRListScreen 더보기 메뉴에 "약관 및 동의 내역" 항목 공간 확보 (v1.5에서 구현 예정)
- 개인정보처리방침 웹페이지 연동 기반 마련

### 📦 배포 정보
- **호환성**: 기존 사용자 데이터와 100% 호환
- **마이그레이션**: 기존 사용자는 자동으로 미동의 상태로 처리, 다음 QR 생성 시 동의 절차 진행
- **성능 영향**: 최소한 (동의 상태 확인용 API 호출 1회 추가)

## v1.0.4 (2025-08-26)

### 🔧 긴급 버그 수정
- **로그인 상태 QR URL 수정**: 프로덕션 서버에서 로그인한 사용자가 생성하는 QR 코드가 IP 주소로 나오던 문제 완전 해결
- **백엔드 환경변수 수정**: `BASE_URL`을 `http://3.39.96.52:3000`에서 `https://api.chackchack.co.kr`로 수정
- **프로덕션 서버 재시작**: 환경변수 변경 사항 반영을 위한 Node.js 프로세스 재시작

### 🛠 기술적 세부사항

#### 문제 원인
- **게스트 사용자**: 프론트엔드에서 QR URL 생성 → 도메인 정상 출력
- **로그인 사용자**: 백엔드 서버에서 QR 이미지 생성 → 프로덕션 서버의 `BASE_URL`이 IP 주소로 설정됨

#### 해결 과정
1. **프로덕션 서버 접속**: SSH를 통해 `ec2-user@3.39.96.52` 접속
2. **환경변수 수정**: `/home/ec2-user/backend/.env`의 `BASE_URL` 수정
3. **서버 재시작**: 기존 프로세스(PID 528505) 종료 후 새 프로세스 시작
4. **동작 확인**: `curl http://localhost:3000`으로 서버 정상 작동 확인

#### 영향 범위
- **해결됨**: 로그인 사용자의 QR 코드 URL이 `https://api.chackchack.co.kr/payer.html?...` 형태로 정상 출력
- **호환성**: 기존 게스트 사용자 기능에는 영향 없음
- **배포**: 백엔드 서버 설정 변경만으로 해결, 앱 재빌드 불필요

## v1.0.3 (2025-08-24)

### 🎯 주요 변경사항
- **손님용 송금 페이지 완전 개선**: 7가지 핵심 UX/UI 이슈 해결
- **할인 기능 완전 구현**: 할인만 있는 QR에서 상품 금액 입력 및 실시간 계산
- **딥링크 최적화**: 토스/카카오페이 앱에 금액 정보 자동 전달
- **QR URL 도메인화**: 서버 IP 주소에서 공식 도메인으로 변경

### 🛠 손님용 페이지 세부 개선사항

#### 1. UI/UX 개선
- **카카오페이 팝업**: 최소 너비 320px 설정으로 안정적인 크기 보장
- **토스 버튼**: 클릭 시 로딩 스피너 표시로 사용자 피드백 강화
- **금액 표시**: 30000.00원 → 30,000원 (소수점 제거, 천 단위 콤마)

#### 2. 할인 로직 완전 구현
- **할인만 있는 QR**: 상품 금액 입력 필드 추가
- **실시간 계산**: 할인 적용된 최종 금액 즉시 표시
- **버튼 제어**: 금액 입력 완료 전까지 송금 버튼 비활성화
- **혼합 케이스**: 기본금액 + 할인 동시 적용 시 정확한 최종 금액 계산

#### 3. 기술적 개선
- **토스 딥링크**: `&amount={계산된금액}` 파라미터로 자동 금액 입력
- **QR URL**: `https://api.chackchack.co.kr` 도메인 사용
- **할인 정보 전달**: QR URL에 `discountType`, `discountValue` 파라미터 포함

### 📦 배포 정보
- **적용 범위**: 백엔드 서버 (손님용 웹페이지)
- **호환성**: 기존 모바일 앱과 100% 호환
- **테스트 완료**: 할인 없음, 할인만, 금액+할인 모든 케이스
